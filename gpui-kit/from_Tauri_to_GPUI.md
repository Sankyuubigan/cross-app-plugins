# Задача: Поэтапная миграция проекта с Tauri (WebView2) на нативный GPUI (`gpui-kit`) без поломки рабочего приложения

## 0. Предварительные требования для ИИ-агента (ОБЯЗАТЕЛЬНО перед кодом)
1. Установи или прочитай актуальные официальные скиллы и документацию `longbridge/gpui-kit`:
   - CLI: `npx skills add longbridge/gpui-kit` (или изучи `skills/gpui-kit/SKILL.md` и `skills/gpui-kit-design-guides/SKILL.md`).
   - Полный справочник: `https://gpui-kit.com/llms-full.txt`
   - Дока по WebView: `https://gpui-kit.com/docs/webview.md` и живой пример `examples/webview/src/main.rs` в репозитории `longbridge/gpui-kit`.
2. **NEVER INVENT AN API:** Не пиши код GPUI по памяти или по аналогии с React / старым GPUI 0.1. Перед использованием любого компонента или метода проверяй реальную сигнатуру в исходниках подключённой версии `gpui-kit` и `gpui-webview`.
3. Если в проекте/окружении подключён наш общий внутренний крейт UI-кита — `D:\Projects\cross-app-plugins\gpui-kit` (Cargo-пакет `my-gpui-kit`: имя `gpui-kit` на crates.io занято опубликованным крейтом longbridge, одноимённый пакет Cargo не разрешает), используй тему, каркас и базовые компоненты из него.

### 0.1. Скиллы gpui-kit: где лежат и как использовать

Два документационных скилла установлены глобально из репозитория `longbridge/gpui-kit`
и обязательны к прочтению перед любой GPUI-работой (п. 1 §0):

| Скилл | Что содержит | Когда читать |
|-------|--------------|--------------|
| `gpui-kit` | Coding Guides (норматив): каркас приложения (`application → init → open_window`), компоненты (Button, Input, Select, Dialog, Tabs, List, DataTable, Tree…), Theme API, механика GPUI (actions, async, entities, events, focus, layout, ElementId, UI-тесты) | Перед любым решением по архитектуре / стейту / публичному API / неймингу / тестам GPUI-кода |
| `gpui-kit-design-guides` | Design Guides (норматив, «requirement, not inspiration»): layout, spacing, визуальная иерархия, палитра, плотность, выбор компонентов, состояния, оверлеи, motion, data-heavy views | ЦЕЛИКОМ перед проектированием/правкой любого экрана и перед ревью UI |

**Где лежат** (глобальная установка — общие для всех проектов и агентов):

- `C:\Users\user\.agents\skills\gpui-kit\SKILL.md` (+ `references/`)
- `C:\Users\user\.agents\skills\gpui-kit-design-guides\SKILL.md` (сам гайд: `references\design-guides.md`)

**Установка / обновление** (флаги обязательны — без них CLI виснет на интерактивных промптах):

```
npx -y skills add longbridge/gpui-kit -g --skill '*' -y
```

**Как использовать:**

- **ZCode:** скиллы подхватываются в список при старте сессии; вызываются автоматически
  при подходящей задаче или вручную: `/gpui-kit`, `/gpui-kit-design-guides`. Содержимое
  `SKILL.md` (+ `references/`) загружается в контекст агента.
- **Любой другой агент (OpenCode и т.п.):** прочитать `SKILL.md` и указанные в нём
  `references/*.md` из путей выше до начала GPUI-работы.
- **Порядок:** API/каркас/компоненты → `gpui-kit`; верстка/дизайн экрана →
  `gpui-kit-design-guides` (отвечать по гайду, не по памяти и не по «как тут принято»).
- Скилл даёт карту API; точные сигнатуры всё равно сверять по сорцам подключённой
  версии (п. 2 §0 — NEVER INVENT AN API).

## 1. Фаза 1: Разделение «Мозга» (Core) и «Лица» (UI) — БЕЗ поломки Tauri
Прежде чем писать любой UI на GPUI, выполни архитектурную подготовку:
1. **Изоляция бизнес-логики (`crates/<project>-core`):**
   - Перенеси всю бизнес-логику, хранение состояния, БД, работу с файловой системой, LLM-движками и логами в чистый Rust-крейт `core`, в котором **ЗАПРЕЩЕНА** зависимость от `tauri`, `gpui` и `gpui-kit`.
   - Замени прямые вызовы `tauri::AppHandle::emit(...)` на абстрактный `EventSink` / `tokio::sync::broadcast`.
2. **Универсальный транспорт (API-мост) для старого веб-фронтенда:**
   - Чтобы существующий веб-фронтенд (`React/Vue/Svelte` в `dist/`) мог одинаково работать и внутри Tauri, и внутри встроенного `gpui-webview` (и даже при откате на Способ 1):
   - Подними в `core` лёгкий локальный `HTTP + WebSocket` сервер на `127.0.0.1:<динамический_порт>` с рандомным токеном авторизации (сессионный ключ) **И** раздавай через него статику собранного веб-фронтенда (`dist/`), чтобы не ловить баги CORS и `tauri://` протоколов.
   - В веб-фронтенде создай единый модуль-адаптер (`src/api/bridge.ts`), через который идут все запросы к бэкенду и подписки на события (вместо прямых вызовов `@tauri-apps/api/*` по всему проекту). Старый `Tauri`-режим должен продолжать работать на 100% без регрессий.

## 2. Фаза 2 (Основной путь — Способ 2): Каркас GPUI + встроенный `gpui-webview` для поэкранной миграции
Цель: сделать главным окном нативное приложение на `GPUI`, внутри которого старые экраны временно крутятся во встроенном `gpui-webview` (`wry`), с возможностью переключать каждый экран/раздел в Настройках.

### Шаг 2.1. Smoke-test сборки (ПЕРЕД переносом логики!)
- Собери минимальное окно `gpui-kit` + `gpui-webview` на Windows.
- **КРИТИЧНО:** Убедись, что бэкенд у `gpui-kit` и `gpui-webview` совпадает (оба на дефолтном `gpui-pre` либо оба с фичей `gpui-fast`), и проект собирается без ошибок C-компилятора (`cl.exe D8050`).
- **ПРАВИЛО ПЕРЕХОДА НА ЗАПАСНОЙ ПЛАН (Способ 1):** Если на данном шаге `gpui-webview` не компилируется, падает на Windows, ломает фокус/клавиатуру/Drag&Drop внутри веб-фронтенда или несовместим с фичами конкретного веб-экрана — **НЕ трать недели на костыли в `wry`, немедленно останови Способ 2 и переходи к Фазе 3 (Запасной план: Способ 1)!**

### Шаг 2.2. Каркас GPUI и переключатель экранов в Настройках
- В корневой конфигурации приложения (`settings.json`) добавь карту маршрутизации экранов `ui_routes`, например:
  `{ "settings": "gpui", "logs": "gpui", "chat": "webview", "studio": "webview" }`
  (по умолчанию для ещё не переписанных сложных экранов — `"webview"`).
- В нативной вкладке **Настройки (GPUI)** добавь секцию «Миграция интерфейса (Экспериментально)» с переключателем для каждого раздела: `[GPUI (Нативный) | WebView (Классический)]`. При переключении на экране должен отображаться выбранный вариант (а также сохраняться выбор после перезапуска).
- При старте/переключении на `"webview"`-экран встроенный `gpui-webview` открывает локальный URL (`http://127.0.0.1:<port>/#/<route>?token=<secret>`), чтобы старый веб-интерфейс открывал сразу нужный раздел без дублирования шапки.

### Шаг 2.3. Жёсткие правила работы с `gpui-webview` на Windows (Airspace Rule!)
В Windows встроенный `gpui-webview` рисуется как нативное дочернее `HWND` окно **ПОВЕРХ** графики GPUI:
1. **Запрещено рисовать GPUI-попапы, Select-списки, тултипы и модальные окна поверх прямоугольника активного `WebView`**, они визуально уйдут под `WebView`!
   - Перед открытием любой модалки/диалога/выпадающего меню GPUI, перекрывающего область `WebView`, обязательно вызывай `webview.hide()`, а после закрытия — `webview.show()` (либо выноси выпадающие меню шапки за границы области `WebView` / используй `NativeMenu`).
2. При переключении на нативную вкладку GPUI обязательно прячь `WebView` через `.hide()` (чтобы он не перекрывал нативный контент и сохранял состояние в фоне), а выгрузку WebView делай, только если пользователь перевёл все экраны на GPUI или явно выключил legacy-режим.
3. Соблюдай правила `gpui-kit`: храни все `Subscription` в `_subscriptions: Vec<Subscription>`, используй `gpui_kit::init(cx)` + `gpui_kit::open_window(...)`, `gpui_kit::actions!` и стабильные доменные `ElementId`.

## 3. Фаза 3 (Запасной план — Способ 1): «Два лица — один мозг»
Используется, **если Способ 2 оказался нестабильным** (баги `gpui-webview`, перекрытия окон, проблемы фокуса/буфера/скролла, нежелание тянуть `msedgewebview2.exe` в одном процессе с GPUI):
1. Отказываемся от `gpui-webview` вообще: убираем зависимость `gpui-webview` из GPUI-приложения.
2. В Cargo Workspace живут два чистых фронтенд-приложения поверх единого `crates/<project>-core` и единой папки данных (чаты, настройки, проекты, БД, логи):
   - `apps/desktop-tauri` — нетронутый классический `Tauri + WebView2` (работает на 100% как эталон).
   - `apps/desktop-gpui` — полностью чистый нативный `GPUI` (0 процессов WebView2, минимальная RAM).
3. В настройках обоих приложений (или в общем лаунчере / `settings.json`) делаем:
   - Переключатель: `Основной интерфейс при запуске: [Tauri (Классический) | GPUI (Новый)]`.
   - Кнопку «Открыть текущее состояние в другом интерфейсе» (сохраняет состояние и запускает соседний бинарник/режим с передачей `--project` / `--tab`).
4. Переносим экраны в `apps/desktop-gpui` по одному, пока классический `apps/desktop-tauri` не станет больше не нужен.

## 4. Жёсткие правила визуала GPUI (чтобы интерфейс не выглядел «чёрной кашей»)
При реализации ЛЮБОГО экрана на `GPUI` (`gpui-kit`) строго соблюдай:
1. **Запрещена дефолтная плоская тема `#09090B` («всё слилось в чёрное пятно»):**
   Настрой (или подключи из `D:\Projects\cross-app-plugins\gpui-kit` / `ThemeRegistry`) чёткую 4-слойную палитру + светлую тему:
   - Окно (`background`): `#181A20` (мягкий графит).
   - Карточки / панели (`group_box` / `card` / `secondary`): `#1F222A` (заметно светлее фона окна!).
   - Поля ввода, списки, деревья (`input` / `list`): `#121419` (утопленное тёмное «корытце» с чёткой рамкой `border: #323846`).
   - Текст (`foreground`): `#E6EDF3` (мягкий белый без ореола), вторичный — `#8B949E`.
   - Шрифт: `"Segoe UI"` (или `Inter`), `14px`.
2. **Цветные акценты кнопок (убираем белые кирпичи):**
   - `primary` = `#1F6FEB` (синий с белым текстом — для главных действий копирования/отправки и активной вкладки).
   - `success` = `#238636` (зелёный с белым текстом — для сохранения/применения).
   - Второстепенные кнопки — нейтральные с чёткой рамкой, не сливающиеся с карточкой.
3. **Чистая геометрия:**
   - **ОДНА компактная верхняя шапка** (иконка + название + вкладки навигации с залитой `.primary()` активной кнопкой + переключатель темы `☀/🌙`). Не дублируй белую системную полосу Windows над кастомной шапкой (используй нативный `TitlebarOptions` / `gpui_kit::TitleBar`).
   - **Никаких кнопок на 100% ширины экрана** внутри `v_flex()` (оборачивай в `h_flex()` или ограничивай ширину).
   - Страницы настроек ограничивай по ширине (`max_w(px(900.))`), списки из 3+ вариантов заменяй компактным компонентом **`Select` (`SelectState`)**, а не простынями радиокнопок.
   - Списки и деревья обязательно оборачивай в контейнер с фоном `#121419`, рамкой `border_1()` и скруглением `rounded_md()`.

## 5. Пошаговый план работы по текущему проекту (не пиши всё за один раз!)
Выполняй работу строго итерациями, после каждой проверяй сборку (`cargo check` / запуск):
- **Этап 1:** Аудит текущего проекта -> план выноса `core` без `tauri` -> реализация `core` + локального моста. Проверка, что старый Tauri работает без багов.
- **Этап 2:** Smoke-test сборки GPUI + `gpui-webview` (или переключение на Способ 1 при блокерах).
- **Этап 3:** Каркас GPUI (шапка, тема, вкладка «Настройки» с переключателем маршрутов `gpui / webview`) + загрузка остальных экранов через `WebView` (или параллельный запуск по Способу 1).
- **Этап 4 и далее:** Перенос по ОДНОМУ экрану за итерацию (от простого к сложному: Настройки/Логи -> вспомогательные списки -> основной экран -> сложные редакторы/Canvas).
